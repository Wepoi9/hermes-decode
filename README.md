# Hermes Decode（Desktop 専用デコード速度プラグイン）

Hermes Desktop のステータスバーに、現在のモデルのデコード速度を1行で表示する単一パッケージの Hermes プラグインです。計測履歴はセッションと実際の接続先ごとに管理し、それぞれ直近10回分の計測値を保持します。セッションを切り替えると表示の参照先も切り替わり、新しいセッションでは最初の呼び出しが完了するまで `—` を表示します。表示するのは、現在使用しているセッションに属する直近の有効な計測値で、他のセッションの値は表示しません。同じセッション内で複数の接続先の計測値が混在し、表示対象を特定できない場合は、誤った接続先の速度を表示しないよう `—` にします。モデルを切り替えると、そのセッションのデコード履歴をリセットし、切り替え前のモデルの計測値が混ざらないようにします。表示値は完了済みの呼び出しから算出したもので、生成中のリアルタイム速度ではありません。

- 速度の定義：直近10回の有効なモデル応答について、出力トークン数の合計をデコード時間の合計で割ります（`Σ output tokens ÷ Σ decode seconds`）。各応答の速度を単純平均するものではありません。
- 表示は公式項目と同じ表記（⚡ アイコン付きで整数 `… t/s`、例 `⚡ 105 t/s`。丸めは公式項目と同じ四捨五入）。未計測のときは値を出しません（`⚡ —`）。項目はステータスバーの右クリックメニュー（「Show in status bar」）に `デコード速度` として並び、公式速度項目（`Tokens per second`）と同じ仕組みで表示・非表示を切り替えられます（切り替えはアプリ側の設定に保存され、再起動後もそのまま）。
- 計測区間は、そのリクエストで最初の実データの delta を受信した瞬間から、終端フレームの処理が完了するまでです。ストリーミング応答のみを対象とし、待機・ツール実行・プロンプト処理・再試行・中断・失敗／不完全終端を除外します。ツール引数・reasoning の delta はデコード生成の開始点なので、その生成時間は窓に含めます（Codex 側は実データを伴う delta だけを数え、引数なしの announce 通知は窓を開けません）。窓を閉じられるのは確定したクリーンな完了終端だけで、failed・incomplete 終端は `None`（未計測）のままです。
- データは原則としてメモリ内にのみ保存します。履歴は（セッション, 実接続先）単位の窓（セッション横断では共有されない直近 10 件）に保ち、窓の保持は少数（LRU 8 窓、セッションのモデル管理台帳も同じ上限で頭打ち）に保ち、無制限に増やしません。永続 DB・ログ・外部 API サーバー・WebSocket サーバー・バックグラウンドポーリングは使いません。窓の読み書きは小さなロックで一貫性を保ち、同時進行の API 呼び出しとプラグイン再読込の両立を確認します。

## 構成

```
plugin.yaml                 # 本体フック post_api_request のみ宣言（ツールは登録しない）
__init__.py                 # 集計（直近10件の窓・合算比）と Desktop へのイベント通知
desktop/plugin.js           # Desktop 表示（STATUSBAR_AREAS.right にメニューで切り替え可能な 1 項目のみ、フォーカス中セッション追従）
patches/decode-hook.patch        # 本体が上流で計測を受け付けるまでの一時的な計測配線（上流 main 基準）
patches/decode-hook-v0.22.4.patch # 公開済み v0.22.4 を動かしている間の計測配線（v0.22.4 タグ基準）
tests/test_decode.py        # 集計の正確性と異常値・境界値・同時呼び出し・再読込の自動テスト
tests/desktop-match.test.mjs # 表示マッチャー（セッション不一致・接続先混在時 `—`）の依存なしテスト
THIRD_PARTY_NOTICES.md      # 本体パッチが上流派生コードを含むことの明示（著作権表示）
.github/workflows/ci.yml    # 公開 CI（プラグインテスト・Desktop 表示テスト・本体パッチ適用と適用後の計測テスト）
```

プラグイン ID とフォルダ名は `hermes-decode` です（イベント名の名前空間になるため `[a-z0-9_-]{1,64}`、ドット不可）。

## インストール

1. このリポジトリを `~/.hermes/plugins/hermes-decode` に配置します（単一フォルダに Python 側と Desktop 側のファイルを配置する）。
2. Hermes 設定の有効プラグイン一覧に `hermes-decode` を追加します（`hermes plugins enable hermes-decode`）。これは本体（Python）側の有効化設定です。
3. Hermes Desktop を起動すると、Desktop 半分がアプリ側のプラグインルートへコピーされ、Capabilities → Plugins の一覧に `hermes-decode` が現れます。Desktop 半分は opt-in（`defaultEnabled: false`）なので、初回はここで項目をオンにします（アプリ側の判断はアプリ側に保存され、設定の有効一覧とは別に切り替わります）。オンにするとステータスバー右側に速度表示が 1 項目だけ現れます。表示のみの切り替えはステータスバーの右クリックメニュー（「Show in status bar」）で行います（当項目は `デコード速度`、公式速度項目は `Tokens per second`。公式項目をオフにすれば当プラグインだけで速度を出せます）。コピー後の更新は再スキャン / 再起動で反映されます。

プラグインを無効にすると、表示項目も `post_api_request` 経由のイベント購読も止まります（追加の後片付けは不要です）。

## 動作条件

- **ストリーミング応答のみ計測対象です。** 非ストリーミング応答、中断されたストリーム、置き換えられたストリーム、失敗した呼び出し、部分応答は未計測となり、窓には入りますが合計へ混ざりません。
- Hermes 本体が `post_api_request` フックへ `decode_seconds`（有限な正の float、または `None`）を渡します。**上流がまだ計測に対応していない間、このリポジトリだけを入れても数値は出ません。** 公表済みの公式 v0.22.4 でも `post_api_request` へ `decode_seconds` は無く、本体パッチ（v0.22.4 基準）を適用しないと速度は出ません。本体パッチを適用するか、対応する上流 PR がマージされたリリースを利用してください。切り替え後は本体ビルドインプラグインを有効化するだけで、本体パッチと上流の旧実装を削除できます。

- 上流 main 基準（`patches/decode-hook.patch`）: 基準コミット `4e58c721c8cf9b51c46636ea84ea6a5cb540880a`、由来（開発元 fork の PR ブランチ先端）`0bbdee3787…`。上流 PR 向けで、上流が受け付けた後の `--reverse` はこちらです。

## 計測と表示の契約（イベント payload）

本体フックから受け取るのは `session_id` / `provider` / `model` / `usage`（正規化済みトークン）/ `decode_seconds`（＋接続 URL `base_url`。URL は不透明な接続先識別子の導出にだけ使い、Desktop へ URL 自身は送らない）だけです。Desktop へ送るのは次に限定します（プロンプト本文・応答本文・reasoning・tool 引数・認証情報・接続 URL・ファイルパス・`usage` 生 dict は送らない）。

| キー | 意味 |
| --- | --- |
| `schema_version` | 契約の版（現状 `1`） |
| `session_id` | Hermes セッション識別子（集計の単位。表示はフォーカス中のセッションに追従する） |
| `provider` | API プロバイダ識別子（情報扱い。表示の照合には使わない） |
| `model` | モデル名（サンプルが自前のモデルを持つ。モデル変更でそのセッションのデコード履歴をリセットし、古い計測を混ぜない。表示側はモデル照合なしでそのセッションの直近サンプルだけを読む：フォーカス中セッションの自前モデルは SDK 経由で取得できないため） |
| `conn` | 不透明な接続先識別子（`base_url` 由来の短いハッシュ。接続 URL は送らない・表出しない。接続先情報が無いときは `null` で、既知の接続先と混在すれば判別不能のまま `—`） |
| `gen` | プロセス世代の識別子（バックエンドの起動ごとに作り直す短い不透明 ID。Hermes だけを再起動して Desktop を開いたままにすると同じ URL の `conn` が変わるため、同じセッションに古い世代の行が残ると判別不能になり得る。Desktop 側は同じセッションへ新しい世代のサンプルが着いた時点でそのセッションの古い世代の行をまとめて退避し、古い接続先に stuck して `—` し続けることを防ぐ。URL 自身は送らない） |
| `tok_per_sec` | 計測済みの整数速度、未計測なら `null` |
| `measured` | 有効サンプルが窓に在るか（未計測の着時は Desktop がその接続先の表示行を空にし、同じセッションの他の接続先の行も退避して表示は未計測へ戻る。Python 側の窓は計測済み呼び出しの履歴だけを保つので、次に着いた計測済みサンプルで表示は復帰する） |
| `valid_samples` | 窓内の有効サンプル数（整数） |

イベント名は `plugin.hermes-decode.sample`（`broadcast_plugin_event("hermes-decode", "sample", payload)`）。受信側は形が合わない frame を無視し、異常な数値（NaN・無限大・0 以下・文字列）を表示しません。

## Hermes 標準の速度表示との対照

Hermes 標準のステータスバー項目は**フォーカス中のセッション**の直近 10 回の API 呼び出しから `Σ 出力トークン ÷ Σ API 所要時間`（`avg_tps`）を計算し、参照先もセッションごとに切り替わります。当プラグインもセッション単位に戻し、両指標の参照先を揃えました（速度の計算だけデコード専有のままです）。表示表記と表示・非表示の切り替えも公式項目と共通です（同じ ⚡ アイコンと `… t/s`、同じ右クリックメニュー）。両方をオンにすると速度が 2 項目並び、右クリックメニューでどちらかをオフにするとその項目だけ消えます（当プラグイン項目の位置は公式項目より外側寄りに並び、公式項目とまったく同じ場所へ差し替えることは現在の SDK では保証しません）。

| 項目 | Hermes 標準（`avg_tps`） | hermes-decode（セッション単位） |
| --- | --- | --- |
| 表示対象 | フォーカス中のセッション | 同じセッション |
| 集計対象 | そのセッションの直近 10 回 | そのセッションの直近 10 回 |
| 計算式 | `Σ 出力トークン / Σ API 所要時間` | `Σ 出力トークン / Σ decode_seconds` |
| プロンプト処理・待機 | 含む | 含まない |
| セッション切替 | 表示対象が切り替わる | 同様に切り替わる |
| 新規セッション | 初回の完了まで `—` | 同様に `—` |
| 他セッションとの共有 | なし | なし |

decode 側の注記: 計測できなかった呼び出し（`decode_seconds = None`）はデコード側の分子・分母に含めないので、同じセッションの直近 10 回でも、両指標が常に完全に同じ呼び出し集合を使うとは限りません。

表示の参照はアプリ標準と同じ `host.state.focusedStoredSessionId`（保存済みセッション ID）に追従します。Python 側フックが渡すのは `agent.session_id` で、基準としてはこの保存済み ID へ直接一致させますが、コンパクション時の ID 継承は 2026-10-16 の実機プロブで確認済みです（圧縮のコミット前後で `session_id` は不変、圧縮後の最初のターンも同じセッション id で完了し、参照先と表示はそのまま継続しました。下記の実機 E2E）。ID が一致しない場合は参照先がサンプルを見つけられず表示は `—` になり、他のセッションの速度を出すことはしません（fail-closed）。ホストが Desktop 半分へ渡すのは main モデルのスラッグだけで、フォーカス中セッション自身のモデルは SDK 経由では取得できません。そこで表示はモデル照合をせずセッションの条件だけで読みます（そのセッションの最新サンプルが読める。main モデルのスラッグを別タブの照合に使わない。同一セッションに新しいモデルのサンプルが着くと、そのセッションの古いモデルの行を Desktop 側でも一括で退避し他セッションの行には触れないため、直前のモデルの速度が表示に残りません）。モデル単位との切替設定は作りません（セッション単位へ一本化）。

## 検証

自動テスト（`python -m pytest tests -q`）:

- `300 tokens / 3 seconds` → `100 tok/s`
- `120/2 + 180/4` → `50 tok/s`（単純平均ではない）
- 未計測サンプルを窓へ混ぜても合計が正しく、11 回目で最古サンプルが除外される
- セッションと実接続先単位の窓が混ざらない（他セッションへは引き継がれず、同じセッションでも 2 つ以上の接続先またぎは接続先ごとに別々）。バックエンドだけを再起動したときは接続先識別子が作り直されるため、新しい世代のサンプルが同じセッションの再起動前の行を退避する（他セッションの行には触れない）
- モデルを切り替えるとそのセッションのデコード履歴がリセットされる（モデル変更直前の計測値が混ざらない。元のモデルへ戻っても古い計測を借りない）。プラグインを再読込すると古いサンプルが一切引き継がれない
- 同時進行の API 呼び出しで窓と LRU の一貫性が保たれること（各窓は計測の直近 10 件ちょうど、窓とモデル管理台帳の保持は上限内）
- `NaN` / 無限大 / `0` 秒 / usage 欠落 / `output_tokens` 欠落で数値を出さない
- 送信 payload が契約キーのみであること（接続先は不透明な識別子で、接続 URL 自身は含まない）、窓の保持が 8 件（セッション・接続先の組、セッションのモデル管理台帳も同じ上限）上限であること、フック登録が `post_api_request` 1 件であること

表示マッチャー・キャッシュのテスト（`node tests/desktop-match.test.mjs`、依存なし）: フォーカス中のセッションに属する直近の計測値だけを出す（モデル照合はしない。ホストがフォーカス中セッションの自前モデルを渡さないため、モデルで絞り込まずそのセッションの最新サンプルを読む）、参照セッションが違えば `—`（新しいセッション・他セッションのタブ）、1 つのセッションに 2 つ以上の接続先が混在すれば `—`（既知の接続先へ一致しない速度を借りない）、接続先情報が無いサンプルが単独なら通常どおり表示、接続先情報が無いサンプルと既知の接続先が混在すれば `—`、同一セッションへ新しいモデルのサンプル着時で古いモデルの行を一括で退避し他セッションの行には触れない、未計測のサンプル着時も同じ退避を行い、さらに同じセッションの他の接続先の行も退避する（接続先の移動後に旧接続先の速度が表示へ残らない。世代とモデルが同じ移動を含む）、バックエンドだけを再起動して接続先識別子が作り直された後は新しい世代のサンプルが同じセッションの再起動前の行を一括で退避し古い接続先に stuck して `—` し続けず他セッションの行には触れない（同一世代の行は当該窓の差し替えのみ、未計測のサンプル着時でも退避は同じ）、行キャッシュは 8 窓で頭打ち（Python 側の LRU と同じ上限）、参照セッションが無い（`null`・空文字）なら数値を出さない、形が合わない入力・ゴミサンプルで落ちない。表示項目の登録方式も同一ファイルで自動検証する（`render` は `data` 内に 1 個だけ・トップレベルの `render` を置かない・メニューへ並ぶ項目名を持ち、公式項目と同じアイコン・`… t/s` 表記を出す）。

## 制約と非目標

- CLI・TUI・組み込み表示には速度を出しません（Desktop 専用）。
- Web ダッシュボード、速度グラフ、時系列解析、履歴 DB、設定 UI、統計・telemetry、他モデルとの比較機能を作りません。
- 表示項目はステータスバー右側の 1 項目だけ（pane・ページ・コマンドを作らない）。
- 上流 Hermes が計測をマージする前、「本体パッチ無しで公式プラグインだけでインストールできる」は要求しません。
